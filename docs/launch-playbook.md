# Open-source launch playbook

## Launch responsibly
1. Run and verify CI on main before announcing the project.
2. Test the CLI on authorized Next.js and Vite projects with synthetic secrets.
3. Enable private vulnerability reporting in GitHub settings.
4. Add topics: security, vibe-coding, developer-tools, nextjs, vite, open-source.
5. Show a short before/after demo with fake tokens. Do not imply a green scan is an audit.
6. Post on relevant Reddit communities only where self-promotion is permitted; disclose that this is a v0.1 experimental CLI.
7. Create small, well-scoped good-first issues; welcome translations, negative tests and simpler remediation instructions.

## Suggested description
Local-first security guardrails for AI-built apps. Catch common exposed secrets and risky client-side env vars, understand why, and fix them before shipping. No accounts or telemetry.

## Track actual utility
Ask 5 Next.js and 5 Vite developers to test it on their own projects. Measure false positives, confirmed fixes, and contributor PRs rather than only GitHub stars. Never request their credentials or private application code.
